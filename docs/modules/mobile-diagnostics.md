# 手机端本地诊断日志

状态：2026-10-15，源码实现；APK 尚未重新打包，系统保存交互待 Android 真机验证。

## 使用

「我的 → 诊断日志 → 导出日志」不要求业务登录或配对。Android 调起系统文件保存窗口，用户选择位置后写入 UTF-8 `.jsonl` 文件；取消不创建成功回执，写入失败明确提示。H5 使用浏览器下载。

页面仅保留「诊断日志」标题和「导出日志」按钮，导出结果使用简短提示；不常驻展示清理策略、数量、容量和补充说明，当前不增加问号或 tips。

文件第一行包含导出时间、时区、构建版本、系统/运行时版本、记录数量和容量状态，之后每行是一个 JSON 事件，可用普通文本编辑器或诊断工具分析。导出的文件由用户保管，不会自动上传，也不会被 App 的本地日志清理删除。

## 清理与容量

- **每天本机时间凌晨 2 点清空上一轮日志，不保留历史多天记录。** 例如 15 日 01:59 的记录在 15 日 02:00 清理，15 日 02:00 起的记录保留到 16 日 02:00。
- 前台定时执行。手机后台暂停、关机、系统杀进程时不能保证准点执行；下次启动、回前台、日志读写或导出时，先按最近一次凌晨 2 点边界补清理，连续停机多天同样有效。
- 复用 `uni` 本地持久存储，使用独立 `callphone.diagnostics.v1` 键；最多 1000 条且序列化大小不超过 512 KiB，先到上限就淘汰最早记录，导出文件注明淘汰数量。
- 普通记录前台每秒落盘，错误立即落盘，进入后台时落盘。进程被强制结束时，最多可能丢失最后一秒尚未写入的普通记录。
- 存储失败保留有界内存记录，可尝试导出并在后续刷新时重试保存，存储状态写入导出文件；日志失败不向业务调用方抛异常。

## 统一使用

`apps/call-phone-uni/src/services/logger.ts` 提供唯一应用日志入口：

```ts
import { logger } from '@/services/logger';

logger.info('update', 'check.started');
logger.warn('network', 'request.failed', { code: 'SERVICE_UNAVAILABLE', durationMs: 15000 });
logger.error('runtime', 'uncaught', { error });
```

模块和事件均使用固定英文标识。详情只传必要状态，不传请求/响应正文、用户输入、组件实例、令牌、凭据或客户资料。入口过滤敏感键、号码、邮箱、地址和本地文件路径，限制对象深度/数量，支持循环引用；Error 仅保留类型、错误码、受限堆栈及可识别的缺失接口名称，不保存可能包含客户输入的原始错误消息。

应用生命周期、全局运行异常/未处理 Promise、Vue 错误处理、`uni.request/uploadFile/downloadFile`、更新状态与版本读取异常、权限探测已接入。网络只记录静态路由、方法、状态/错误码、耗时和本机生成的关联 ID，不读取请求/响应正文到日志；路径中的动态参数、主机和查询串不保留。第三方运行时内部输出和后端既有日志不由此模块接管。

`AGENTS.md` 已写入统一入口规则；`tests/diagnostics.test.cjs` 检查手机端源码不直接输出 `console`，并覆盖清理边界、跨进程恢复、容量、脱敏、存储失败、网络回调及 Android 保存/取消/超时/失败。

## 代码位置

- `src/modules/diagnostics/core.ts`：持久记录、脱敏、容量、凌晨 2 点边界和导出内容。
- `src/services/logger.ts`：应用单例、前后台清理/落盘调度、网络日志和运行环境摘要。
- `src/modules/diagnostics/export.ts`：Android SAF 用户选址保存、H5 下载，不申请全部文件权限。
- `src/components/DiagnosticLogs.vue`：我的页面日志卡片。
