## 模块职责

| 层 | 职责 | 约束 |
|---|---|---|
| 通用核心 | 检查协调、版本决策、状态流转、去重、错误分类、下载进度、有限重试 | 不依赖客户、通话、配对、电话号码或业务数据库；用注入依赖处理平台操作 |
| 版本源适配 | 读取并校验发布元数据，区分无更新、可选更新、强制更新 | 接入旧升级中心或新的发布服务；不能把服务不可达视为无更新 |
| 平台适配 | 读取应用身份/版本/能力，下载和校验安装包，请求安装或打开支持的商店入口，清理临时文件 | 首期按实际 Android 发布方式实现；其他平台显式报告能力，不伪装成功；资源包更新仅在兼容性核验后启用 |
| 应用接入 | 注册适配器、启动/回到前台的检查策略、手工检查入口、更新提示，以及是否允许安装的判断 | Call Phone 用业务回调阻止正在通话或尚未安全保存结果时安装/重启，核心不导入通话服务 |

核心流程应能由不同应用与 UI 复用；不先承诺跨 uni-app/Electron 的具体共享目录，确定依赖和打包兼容性后再落位，避免把平台 API 放入共享核心。

## 候选接口与数据契约

以下为实现基线草案，尚无已上线 API；开发时按选定的版本源映射，不在文档中把路径当作既有接口。

- 入口：创建更新服务时注入 VersionSource、PlatformAdapter、安装许可回调及提示策略；对应用暴露 check、download、install、cancel、状态订阅与 dispose。
- 检查输入：应用标识、平台、架构、发布渠道、已安装 versionCode/versionName，以及需要时的原生基座/资源版本。不得传客户信息、通话记录、录音或业务队列。
- 发布信息：发布 ID、目标应用/平台/架构/渠道、版本名称与可比较版本号、发布时间、说明、是否强制、最低兼容基座、制品类型和地址、文件大小、摘要与可信校验信息；商店更新返回明确商店入口。
- 身份和兼容性：版本号只在同应用、平台和渠道内比较，不按版本名称字符串排序；不兼容制品不提供安装。下载摘要与可信发布元数据联合校验，不能把来自任意响应的哈希视为可信签名。
- 安装入口：只有制品校验通过且应用允许安装时可执行；用户取消、权限拒绝、安装失败和等待安装需分别表示，调用安装 API 成功不等于系统安装完成。
- 生命周期：启动检查与手工检查共享同一进行中的请求；失败后可再次发起，同一发布重复提示受策略控制；取消/销毁后旧回调不能重写新状态。普通更新失败不阻断应用启动。
- 认证：若版本源需要认证，注入对应授权机制；公共发布查询不附带客户业务设备密钥。可下载域与重定向规则由发布适配器校验，日志不保存令牌或带签名下载地址。

## 状态、错误与应用交互

状态建议为 idle、checking、upToDate、available、downloading、verifying、readyToInstall、installing、cancelled、failed；失败保留阶段和可重试标志。没有网络、版本源故障、无更新、不兼容、校验失败、用户取消和安装失败分别展示，校验失败必须清理制品并禁止安装。

“自动更新”首期指自动检查并按发布策略提示，安装按平台要求与用户操作执行。强制更新可在安全时机要求升级；通话进行中先提示待处理，不能立即重启。通话结果尚未安全保存时不进入安装，业务阻塞解除后重新检查许可。下载重试不创建重复安装任务，临时文件有明确的取消与失败清理策略。

版本发布来源、是否采用旧升级中心、强制更新政策及正式制品分发方式在实施时核实；AppID、包名、签名与正式版本号的发布核验仍属发布阶段，不通过此设计替代。

## 验收清单

- [ ] 通用核心可用替身版本源/平台适配器运行，不导入 Call Phone 的客户或通话服务。
- [ ] 启动检查和“我的”手工检查共用一个任务；无更新显示正确，服务不可达可重试且不显示为已是最新版。
- [ ] 可选/强制更新、同渠道版本比较和应用/平台/架构/基座不兼容制品筛选有回归覆盖。
- [ ] 下载进度、取消、网络失败、有限重试及摘要/可信校验失败处理正确；错误制品不能安装。
- [ ] 安装权限拒绝、用户取消、安装失败与完成后的版本核对在目标 Android 真机验证；不把安装请求发起当作安装成功。
- [ ] 反复检查、重复点击安装、切前后台以及 dispose 后旧回调不产生重复下载/安装或污染新状态。
- [ ] 进行中的通话、未安全保存结果会推迟安装；业务允许后可继续，不遗漏已保存的待同步记录。
- [ ] 初期只声称支持已经实测的平台及制品类型；其他应用接入只需替换适配器/策略，不复制业务流程。

## 2026-10-11 实施补充

已实现 `apps/call-phone-uni/src/modules/app-update/{core,source,android}.ts`，由 `services/updates.ts` 注入通话与安全保存许可。旧 `.references/CallPhone` 中存在升级中心云函数，但缺少客户端依赖，且当前工程没有可核验的 uniCloud 部署配置，因此首期使用独立的签名 HTTPS 清单适配；以后接入旧中心需实现相同 VersionSource 并保留可信校验。

配置项：`VITE_UPDATE_MANIFEST_URL`、`VITE_UPDATE_PUBLIC_KEY`（RSA SPKI DER base64 公钥）、`VITE_UPDATE_DOWNLOAD_ORIGINS`（逗号分隔 HTTPS origin）、`VITE_UPDATE_CHANNEL`。不填时自动检查不打扰启动，手工检查返回可理解错误；不把服务故障视为最新版。

清单格式为 `{ "payload": "精确 JSON 文本", "signature": "RSA-SHA256 base64 签名" }`，签名针对 payload 原始 UTF-8 字节。payload 内容为 `{ "release": null }`（无发布）或 `{ "release": { ... } }`，字段见 `core.ts` 的 Release；必须包含应用、平台、架构、渠道、版本号、最低基座、发布时间、强制标记，以及 APK URL、字节数、SHA-256 和包名。发行方离线执行 `node scripts/sign-app-release.mjs release.json private-key.pem signed-manifest.json`；私钥不得打包到客户端。每个平台/架构/渠道可配置各自清单地址。

Android 下载走原生下载器；下载 URL origin 必须在配置允许列表内，清单签名在下载前验证，实际 APK 的大小、摘要、包名、版本号和与已安装应用相同签名在下载后及安装前验证。原生下载器的重定向逐跳策略尚不能由该适配器完整观测；正式发布应使用不重定向的固定制品 URL，不能宣称已验证所有 CDN 重定向行为。签名轮换和 WGT 更新未支持。

安装请求发出仅进入 `installationRequested`，返回前台重新读取实际版本核对；权限拒绝有系统设置入口，用户取消后可重试。可选更新不阻塞正常业务；强制更新阻止新外呼而保留当前通话结束/保存路径。安装中及等待系统安装时同样禁止新外呼。已安全保存的待同步任务不因更新删除。

实现与测试进度、真机和发布源条件见[修复实施记录](../reviews/2026-10-10-uni-remediation-progress.md)。以上代码接入不等于正式升级发布完成，原真机验收复选项暂不勾选。
