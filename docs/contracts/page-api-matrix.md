# 页面、数据表与 API 契约总表

本文件是逐页实现的拆分清单。页面只对应应用中心第三级菜单；详情、创建、复核、配对等是所属页面内的抽屉、弹窗或状态。字段类型、ID、时间、分页、幂等、租户和敏感信息规则统一遵循[公共契约](api-data-conventions.md)。详细字段与状态机见各[模块文档](../README.md#模块文档)。

## 所有权与落库规则

| 领域                                                 | 表/能力所有者                           | 首期落点                                                | 数据来源/约束                                                             |

## 页面级 API 清单

路径约定：本表按当前实现映射记录接口。Call Phone PC 管理端使用 `/callphone/**`，复用的 Yudao 系统能力使用 `/system/**` 或 `/infra/**`，移动端兼容入口使用 `/api/v1/mobile/**`，匿名公开跳转使用 `/callphone/public/**`。产品级稳定 API 的逻辑契约仍遵循[公共数据/API 规则](api-data-conventions.md)的 `/api/v1`；后续网关适配不得把 Yudao 内部路径当成产品 API。权限列记录当前实际 Yudao permission key；业务写操作须按各模块契约执行幂等键、版本校验和服务端 tenant/角色/行/字段范围检查。

## 实现批次与依赖

1. **基座与外呼闭环**：Yudao 登录/租户/角色/API 封装；设备、配对、派发、通话记录。先让 PC 发起、手机接受/拒绝/过期、结束回填、PC 查看详情完整闭环。
2. **客户与线索**：在 `yudao-module-callphone` 内实现自有 `cp_*` 表与字段保护，再逐页实现客户、跟进、阶段、线索池、分配、转化和归档；不复制或扩展 CRM 源码。外呼 UI 组合使用本模块公开客户/线索 DTO。
3. **设置**：先做用户复用、设备配对、权限和业务配置；备份、审计、诊断后续接入。
4. **拓客**：渠道、活码配置、HTTPS 落地页与匿名扫码 302/日统计已接入；生产部署需配置可公开访问的 Call Phone 服务域名。识客身份匹配仍需完成授权与隐私设计；获客链接通过 `cp_ref` 与已有线索 `sourceCode` 做客户部署内归因，不提供匿名收集个人信息的接口。
5. **AI 与企微**：AI adapter 在核心服务字段合同及出站授权经评审后接入；企微、存档、质检在应用授权/接口能力盘点后启用。不可用的页面需呈现清晰的未连接状态，不显示虚构数据。

## 开始编码前的阻断项

- 确认 Call Phone 客户/线索自有 schema、手机号密钥管理与字段权限；如果需要导入既有 Yudao CRM 数据，另行设计一次性迁移映射，不建立运行时跨模块表依赖。
- 确认 uni-app 拨号/录音插件回调字段及 Android/iOS 差异，并冻结移动端事件 payload。
- 确认 Call Phone 新后端模块 Maven artifact、数据库 migration 目录和权限初始化机制，避免直接改模板生成文件。
- 确认客户自部署安装方式、首个 API Base URL 配置方式、TLS 与对象存储；外呼配对需要两端可访问同一服务。
- 企微同步、会话存档、云端 AI 均为外部能力依赖，需先核验接口授权，不以原型页面替代服务端能力。
