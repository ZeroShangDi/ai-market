# PC / Android 实机联调验收

日期：2026-10-10。前置条件和未验证项见 [本轮审查报告](2026-10-10-mobile-pc-audit.md)。本清单用于真实数据服务与真机，带 `preview=1` 的电脑页面和开发 mock 不计联通验收。

## 1. 准备运行环境

1. 使用本分支构建后端和 PC；执行已有数据库迁移，保留现有数据，不删除数据库卷。CallPhone 加密密钥、授权服务及客户侧地址按 [部署文档](../architecture/backend-deployment.md) 配置。后端模块测试成功不代表数据库迁移已执行。
2. PC 与手机使用**同一客户侧服务、同一租户/工作区、同一员工账号**。账号至少有客户查询、设备配对管理、外呼派发权限；真实授权快照允许外呼。手机可访问 HTTPS 服务域名，或测试局域网中的电脑 API 地址。
3. 本地 Compose 默认 API 为 `127.0.0.1:48080`，手机访问 `localhost` 只会访问手机自己。如果要做同一 Wi-Fi 联调，从 `apps/ruoyi-vue-pro` 执行：

   ```sh
   CALLPHONE_API_BIND_HOST=192.168.1.10 docker compose -f compose.local.yml up -d --build server
   ```

   将示例 IP 换成电脑实际局域网地址；只调整 API 服务的监听地址，MySQL/Redis 保持本机监听。此命令是操作说明，本轮没有重新启动或对外开放现有服务。请确认网络可达与系统防火墙策略。PC 登录地址与手机服务地址可以域名不同，但必须指向同一后端；若 QR 中填了服务地址，必须与手机当前配置一致。
4. 手机以真实模式构建 `VITE_MOBILE_MOCK=false`。打开登录页填写服务 origin（例如 `http://192.168.1.10:48080`）、工作区 ID、员工账号密码。令牌自动刷新；服务器启用验证码时由用户拖动滑块完成正常登录验证。
5. 使用 HBuilderX/DCloud 对应账号重建包含原 `leven-call-CallModule`（插件 ID 16275）的 Android 自定义基座/安装包，包含 Barcode 模块与相机、电话、录音文件所需权限。`pnpm build:app` 只生成 App 资源，不生成 APK；热更新不能加入缺失原生模块。H5 不执行原生拨号或相机扫描；手工配对码仍可用。

## 2. 顶栏与数据

- 冷启动工作台、客户、详情、我的、登录页；状态栏时间/信号区与页面标题之间无额外空原生导航条。左侧标题/返回图标与右侧动作图标位于自定义顶栏；原 SVG 外观保持。分别检查有刘海和普通 Android，旋转/返回/滚动后标题仍稳定。
- PC 创建一位本人负责的测试客户。手机客户页切到“全部”后能看到；“今天/最近”按通话记录筛选，刚创建但未通话的客户不必出现在“今天”。手机详情显示相同客户信息与近期记录。
- 手机快速切换“今天/最近/全部”，旧请求不能覆盖新筛选；退出再进页面只保留一个轮询。不同工作区、非本人数据与没有外呼权限的账号不应获取可拨完整号码。

## 3. 扫码配对

- PC“电脑与配对”创建配对码，看到二维码、六位码与约 300 秒倒计时。可选填写手机可达服务地址。关闭再点“继续配对”，二维码与码保持；过期后可以重新生成。
- 手机“我的 → 本机与配对 → 扫码配对”扫描 PC 二维码，检查确认信息，确认认领。PC 在轮询后显示已配对设备，手机立即发送心跳，PC 显示在线。再测手工输入六位码。
- 使用无关 QR、过期码、已使用码、另一工作区/不同服务 QR，不能显示配对成功，也不能覆盖现有账号身份。
- 取消未认领码；若同时被手机领取，PC 以服务端最终状态为准。PC 解绑设备后，手机旧设备凭据必须拒绝请求并提示重新配对，账号登录态保留。
- 应用重启后账号令牌和设备密钥不从明文存储恢复，需重新登录；Android 应恢复经 Keystore 加密的原设备身份并由服务端复核，无需重新配对。切换账户/工作区不得恢复别人的凭据。

## 4. PC 派发与手机拨号

- 客户列表点“发起外呼”，通话页抽屉直接带入该客户；选当前在线 Android，发送后 PC 显示排队。连续点击发送不能重复派发。
- 手机在客户列表、详情、我的、工作台前台均可看到公共派发入口，**只有用户确认接受后**调用本机原生插件。检查目标号码与服务端权限一致。拒绝另一条派发后，PC 显示拒绝原因/状态。
- 使用自有测试号码，分别测试接通、无人接听、忙线/拒接。用户手工确认结果，PC 通话详情、列表/统计与手机客户最近记录一致。接通时长保留插件观测值，长时间响铃但未接通应是零通话时长；延迟填写结果不增加通话时长。
- 通话中暂时切到系统电话界面再返回，结果页仍属于当前客户；页面返回/新拨号在当前记录未完成前阻止误丢失。来电回调不能把无关来电的录音/时长关联到该客户。
- 插件不可用时不能创建假的服务端通话。插件明确失败时记录失败/其他；插件 15 秒无回复表示状态待核对，不能自动判定未拨号，允许用户按本机实际结果确认。
- PC 取消排队派发后手机不能再拨；已接受/已完成时不能错误覆盖状态。设备撤销和派发过期也应由服务端拒绝。

## 5. 同步、录音与异常

- 通话结束断网保存：明确显示待同步，保持应用进程，恢复网络后重试；PC 只有一个通话记录/事件。多个页面同时触发重试不会重复上传或移除别的任务。
- access token 过期同时发多请求：刷新一次后用同一事件 ID/幂等键重试；账户切换时旧请求结果不能混入新账户。
- 支持录音的基座中，开启本机录音/文件权限，完成结果后上传，PC 与手机可播放有权访问的录音；另一个设备/账号不可读取。无录音时明确显示无录音，不显示伪播放按钮。
- 服务返回 HTTP200 但业务 code 非零时，页面必须显示失败，不能继续“配对成功/保存成功”。403、设备撤销和不可达分别检查。
- **验证 Android 安全持久化恢复。** 离线安全保存后杀进程，登录相同账户和工作区，确认原设备和事件/上传幂等键恢复、不重复落库。人为制造存储失败时必须阻止假成功；H5/iOS 应明确提示不支持。

## 6. 可复现的服务端链路检查

仓库根目录有 [联调脚本](../../scripts/callphone-integration-smoke.py)。默认读取现有 API，只提示输入测试账号/密码，不打印凭据或客户内容：

```sh
python3 scripts/callphone-integration-smoke.py --base-url http://127.0.0.1:48080 --tenant 1
```

需要真实服务已运行。服务器启用验证码时先正常登录，通过安全环境变量提供 `CALLPHONE_ACCESS_TOKEN`，不要把真实 token 写进文档/提交代码。也支持 `CALLPHONE_BASE_URL`、`CALLPHONE_TENANT_ID`、`CALLPHONE_USERNAME`、`CALLPHONE_PASSWORD`。

在专用测试工作区运行完整服务端流程：

```sh
python3 scripts/callphone-integration-smoke.py --base-url http://127.0.0.1:48080 --tenant 1 --exercise
```

它创建标记为“集成验收”的合成客户和虚拟 Android 设备，验证配对、心跳、跨端查询、派发接受、结果回填、幂等重放、拒绝、取消及撤销。结束尝试归档自己创建的客户与撤销虚拟设备，保留审计/通话记录。脚本不会加载电话插件或拨号，不能替代第4、5节真机检查。真实环境不可达时只检查脚本语法不计链路通过。

验收结果应记录设备型号/Android版本、基座版本、服务提交、租户、测试步骤及结果。不要记录实际凭据或完整客户号码。
