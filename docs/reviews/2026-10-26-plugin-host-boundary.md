# 插件底座缺口与边界核验

## 现有实现可复用

- `work-plugins.js` 已支持受管理目录中的工具、技能、连接适配，不另写模型工具执行器。
- `WorkStore` 已支持账号隔离、幂等提交、待办与持久化，不新增任务执行框架。
- 能力中心已支持插件目录、安装、启停与连接状态，增量支持可运行的内置包即可。
- 应用注册表已有原生页面导航，但没有插件页面装载；已有内置目录只有展示元数据。

## 确实缺少的通用承载

- 受管理插件的常驻 activate/close 生命周期与独立数据目录：原 activate 仅在某次 Work 执行时创建工具。
- 鉴权管理调用及公开回调转发：原服务只有固定 Work 资源接口；回调凭据的验证和身份绑定由插件负责。
- 插件自有页面进入应用中心：构建器依据包清单装载 Vue 页面，客户端不实现规则 CRUD、cron、工作提示词、事件参数等业务。
- 已有会话 API 的通用调用接口供受管理插件使用，沿用内部鉴权；不会自动添加已连接插件或代批待办。

## 明确移回插件

- mcp-cron 的版本、Docker 构建、MCP 依赖、进程启动关闭与工具白名单全部归定时包。
- 订阅与时间规则、持久化、重试、去重、管理页面和工作提示词都归各自包。
- 删除上一版 Work 自动挂载插件以及默认添加全部已连接能力的改动。
- 底座不含 schedule/event 专属操作名称或固定调度依赖；会话来源类型另作第四项修改。

## 验证

`plugin-host.test.js` 使用无关的 inventory 插件验证装载、调用、回调和卸载，无定时或事件包依赖。插件自己的规则与执行用例单独保留。生成的页面和部署包为构建产物，不作为客户端业务源码维护。
