# 定时任务与事件触发插件

实现范围：两个独立内置包，应用中心的管理页面由包内 `page.json` 声明，通过构建脚本生成页面清单。插件包含工具、技能、运行逻辑和独立持久化；宿主仅提供生命周期、身份传输与 Work 接口。会话保存 `source_type` 和可选 `parent_id`，历史按手动、语音、定时、事件筛选，默认手动。历史纯语音转录会话根据消息与请求记录关系回填语音来源；无可靠依据的旧会话保持手动，不根据标题猜测来源。

定时包通过标准 MCP 调用独立 mcp-cron 进程的 HTTP 调度能力；固定上游提交 `0251d61a1fe1175ce96df46d4257499018f8f9e0`，不修改其源码。镜像包含其 AGPL-3.0 许可证及同版本源码归档 `/opt/mcp-cron/source.tar.gz`，项目地址 https://github.com/jolks/mcp-cron 。只调用 list/add_http/update/remove，调度进程不直接暴露给模型或公网。单次任务使用带时区时间，周期任务五段 cron 和 IANA 时区；单次到期通过分钟级调度送达，可能延迟不足一分钟。重复任务停机期间不补发所有错过周期。

事件接收 URL 是持有者可使用的凭据，不应公开。JSON 通知持久化后返回接收成功，后台调用原 Work 创建和提交接口。创建聊天及提交工作沿用同一稳定请求编号；输入指定 Idempotency-Key 时按订阅去重。未提供事件编号的通知每次均视为新事件，不能保证来源重复通知去重。一条通知对应一项工作，批量通知和缺失对象 ID 的处理由工作说明决定。已有执行授权依然由 Work 服务端待办控制，邮件正文不能授予权限。

运行记录区分已接收/排队、工作已提交和触发失败，实际工作结果在关联会话中查看。事件参数上限 6000 字节，工作提示词上限 5000 字符。事件提交采用有界重试；暂停/停用阻止新触发，已创建 Work 不被删除。规则和投递队列位于 `/data/plugins/<plugin-id>/state.json`，原子替换、进程内串行写入；本版本仅支持单个 Agent 写入者，不共享该目录启动多副本。

部署需在 Agent 环境配置 `AI_SERVICE_URL`、与会话服务一致的 `AI_INTERNAL_TOKEN`、用户可访问的 `PLUGIN_PUBLIC_URL`（以 `/api/v1/plugin-hooks` 结尾）。默认调度回调走容器内部 localhost。外部 HTTP 目标必须是 `PLUGIN_WEBHOOK_HOSTS` 中部署方允许的 HTTPS host；本系统事件地址可直接使用。当前 Tailscale 地址仅适用于能访问该网络的发送方；外部邮件供应商直接推送需另行配置可访问的 HTTPS 地址。本轮未建立任何真实邮箱订阅。

未实现供应商专用验签/握手/续期，不能宣称可直接接所有邮件供应商。服务要求 JSON POST；不兼容的来源应通过已有工具或经用户确认的定时查询触发。

验证与发布结果：

- 底座、Work 和两个插件共 48 项 Node 测试通过；手机端 232 项测试及类型检查通过；会话服务 21 项、网关相关 12 项、语音历史 4 项测试通过。
- 无关 inventory 示例验证通用装载、管理调用、回调和关闭，不依赖两个业务插件。真实 Linux mcp-cron 进程完成定时 HTTP 通知与删除；发现 SQLite 短暂锁竞争后，在定时插件内增加仅针对 SQLITE_BUSY 的有界重试并复测。
- 三个后台镜像已部署；会话数据库迁移至 V2，内部来源查询与两个插件管理接口返回 200，Agent、网关及重启后的语音健康检查通过。会话服务没有 actuator 健康端点，使用鉴权业务接口验证。
