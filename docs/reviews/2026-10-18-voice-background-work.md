# 语音交办后台任务：开发验证

日期：2026-10-18。未发布；等待新资源与服务恢复后统一打包真机测试，不改变静默退出策略。

## 实际行为

1. 快速模型继续处理普通聊天，`ask_agent` 继续承担可打断的只读查询。新增 `propose_task` 只生成任务提案，不能执行任务或批准操作；纯 H5 没有宿主桥时不开放该工具。
2. Android 原生确认窗口显示完整任务内容。桌面语音使用悬浮窗口确认，不进入业务 App 页面。点击创建后，宿主依次调用既有鉴权的 AI 会话创建、Work 会话创建与消息接口；拒绝不执行。
3. 同一提案 UUID 绑定内容、角色和创建/消息幂等键。提交超时允许相同键重试；不把未知结果谎报为成功。音频会话关闭不取消已确认的提交，也不请求 Work 的 interrupt/close。
4. Work 在服务器独立执行、持久化消息/结果和原生交互。角色人物卡、交流技能在任务开始时读取服务端发布目录并保存快照；不额外授权工具。执行过程中的新授权或问题仍在工作台处理。
5. 宿主在语音、文字聊天或桌宠在线时每 5 秒查询工作状态。语音等用户发言、模型回复与播报结束后播报简要结果；文字聊天展示结果与查看入口；没有聊天则显示宠物气泡。都不可用时不请求通知，用户下次进入工作台查看未读结果。
6. 通知不标记已读。音频尾部用同队列结束标记确认已送完；用户插话时不确认该通知，结果仍能通过文字/工作台查看。服务器任务不会被声音打断取消。客户端本次运行按任务与事件序号去重；重启后未读结果可能再次提醒。

## 检查

- 手机端 210 项测试、类型检查、App 前端构建通过。
- 独立语音 14 项测试通过，包括本机 UDP WebRTC、提案边界、等待聊天空档、音频结束确认、被打断不确认、旧播报停止不能把用户发言误判为空闲。
- Agent 35 项测试通过，包括带角色的任务并发重试只运行一次、观察者断开不取消、结果持久化与未读、重新加载后角色快照与权限隔离。
- Android 语音/桌宠 Kotlin 编译通过，包含任务确认悬浮窗口与双向 WebView 桥。
- 手工核对：确认与完成通知模块不调用 Work 取消接口；模型没有直接提交任务/批准工具操作的语音工具；宿主不写入任务正文诊断日志。

## 尚未验证

已部署新网关、AI、Agent 与 Mac 语音代码，并生成、发布 1.0.20（118）APK。合成配对设备验证网关票据、专网 HTTPS、真实 WebRTC 与票据重放拒绝通过，测试设备已撤销。自动任务检查使用合成任务和模拟执行器验证控制链路，不代表真实模型交办已跑通。

真机联调需验证：桌面确认与拒绝；创建后继续聊天及关闭语音；任务完成时语音播报、文字入口、桌宠气泡三种路由；关闭 App 后服务器仍执行并在工作台补看；网络超时复用同一任务；等待授权入口；资源切换不影响既有任务。

App 进程完全退出时没有额外推送服务；结果由服务器保留，重新打开补看。服务重启时现有 Work 按中断/结果不确定处理，避免自动重放有副作用的操作，这次没有改为自动恢复执行。
