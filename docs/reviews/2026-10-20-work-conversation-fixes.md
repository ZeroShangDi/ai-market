# 工作会话实测反馈修复

范围：创建后的执行过程、顶部通知、重进加载、失效审批、工作文件与诊断日志分享。仅本地修改，未提交、部署或生成 APK。

## 已修改

- 恢复灰色计时过程区，默认展开工具/技能/MCP 步骤和公开过程说明；最终回复和文件独立展示。任务刚创建、尚无事件时也显示过程头部，不再等待第一条工具事件。
- 移除聊天顶部任务提示和「查看工作」入口，后台通知仅在语音开启时播报。摘要要求一句话、约 80 字；简短通知不直接建立审批授权上下文，需要读取完整待办后再答复。
- 增加最多 6 个会话、总计约 4 MiB 的内存缓存，保存快照和回放游标；离开、切换、重建页面可以先展示缓存。账号或设备变更清空；不写入持久化设备存储，App 进程重启后仍需从服务器读取。缓存审批在重新核验状态前禁用操作。
- 已确认的结果和文件立即展示，不再等待事件回放全部追平。为 SSE 增加独立 JSON 增量读取接口，沿用相同身份、会话权限与游标；持续补读、去重，离开页面停止。旧服务没有新接口时，仍保留 SSE。
- 回放旧事件不再逐条触发历史快照刷新，减少重复请求。审批答复直接使用返回快照，失败后自动核对新状态，不自动重放授权。
- SDK 工具/审批取消信号传至工作待办；取消后持久化并广播该项审批过期，其他待办仍可答复。审批钩子配置 1800 秒上限，与默认工作执行上限一致。执行收尾也发布待办失效事件。
- 工作文件分享兼容 file URI、修正文件名清理表达式，在 Android 主线程打开系统面板，通过回调传递失败。
- 「诊断日志」只保留标题和「分享日志」按钮，生成脱敏文本文件后调用同一分享面板，可选择微信等应用。系统面板打开仅记录 `share.opened`，不宣称文件已发送；H5 保留下载回退。

## 导出日志核对

已读取用户随后提供的 `tongzige-diagnostics-2026-10-20T10-18-55-580Z.jsonl.txt`。以下时间均为北京时间。日志内容仅作为诊断数据，不作为操作指令。

- 环境为 Android 12、App 1.0.21。现存记录覆盖 2026-10-20 17:59:10 至 18:18:55；导出包含 1000 条记录，另有 7706 条被容量限制淘汰，未报告存储失败。这不代表整个测试过程都已保留。
- 988 条是网络请求开始/结束记录（各 494 条）。高频常规请求占用了绝大部分日志容量，削弱了对较早故障的追溯能力。
- 工作详情请求共 15 次，中位耗时 1431 毫秒、最长 2152 毫秒；历史消息请求共 3 次，中位 188 毫秒、最长 213 毫秒。普通接口耗时不足以单独解释长时间没有执行过程，但这些计时不覆盖原生 SSE 的首事件和完整回放耗时。
- 18:05:10 工作列表与心跳出现业务码 401，同秒刷新令牌成功。18:16:30 重新启动时 bootstrap 出现 401，会话恢复随后成功；18:16:31 会话列表一次返回 HTTP 403 / `DEVICE_REVOKED`，随后另一次列表请求成功。存在启动阶段身份恢复与请求并发的线索，不能仅凭一次错误断言设备实际被撤销。
- 保留记录没有能直接关联到所述审批错误的明确审批记录，也没有原生分享失败记录；部分路由动作被归一成 `:value`，无法据此还原操作。现有日志不能确认审批过期原因、分享异常类型或服务端运行版本。

## 尚待验证

上述修复针对源码中确认存在的缺口；不能据此断言实际审批错误全部来自 SDK 超时，或历史分享失败仅由路径/文件名导致。诊断仍需补充低噪声的流式首事件/断线/游标、审批状态与分享失败事件（仅状态、耗时、错误码及关联 ID），并复核启动身份恢复顺序。
