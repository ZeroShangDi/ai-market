# 工作文件分享、外部接收与语音音质排查

- 用户反馈：工作文件点击分享即报错，未出现系统分享面板；日志分享正常；外部应用打开文件到工作会话仍不可用。具体报错、文件类型和来源应用尚未取得。
- 两种分享最终复用 WorkFileShare，但日志在原生 cacheDir 生成临时文件，工作文件此前从 uni-app 的保存目录传路径。原生路径检查仅允许应用私有目录与 externalFilesDirs；尚未取得失败手机的实际路径，不能将目录差异标为已实机确认的根因。
- 工作文件改为复用既有鉴权 `/content` 接口获取 Base64，在原生 cacheDir 写临时二进制副本，再调用同一分享器。保留 8 MiB 限制、临时只读授权和清理；不扩大允许读取的本地路径。此路径需要联网，打开文件仍使用原本的本地缓存。面板打开不等于文件已经发送。
- 外部接收去掉 Array.at 依赖；创建工作会话等待聊天加载结束，再响应初始化与加载状态变化。失败保留文件，避免加载状态变化导致重复创建重试。缺少实际设备，原生 Intent 接收和文件授权仍需真机验收。
- 当前没有 ADB 连接设备。新增分享原生接口必须重新构建安装包，本轮不发布安装包，不把前端构建视为原生或手机验收。
- 验证：手机自动测试 231 项全部通过，包含受鉴权内容分享与二进制原样传递、文件本地缓存、无 Array.at 环境的外部接收和失败保留；类型检查及 App 前端构建通过。尚未执行新增 Kotlin/UTS 接口的安装包原生编译。
- 音质：按当前配置对三句合成文本运行真实 TTS → PCM → ASR，音频分别 2.16、2.72、3.28 秒，三次字错误率均为 0。未复现重复首字；该测试不覆盖 WebRTC、手机缓冲、外放及蓝牙，也不能排除杂音。未修改生成参数或声称音质已修复，需要故障音频及播放场景进一步定位。
