# 手机更新摘要

每次定义待发布手机版本时，由 AI 或发布人员依据本次实际变化编写 `<versionName>.json`，与 APK 的版本名称保持一致，例如：

```json
{
  "versionName": "1.0.26",
  "highlights": [
    "更新提醒更简洁，重要变化一眼看清",
    "新增更新进度弹窗，随时查看下载状态"
  ]
}
```

上面仅为格式示例，不代表已创建或发布该版本。

- 保留 1～3 条主要变化，每条最多 32 个字符，合计最多 90 个字符，不含序号、Markdown 或换行。
- 合并同类变化，用用户能理解的功能和体验描述；不堆砌内部模块名、接口、部署、签名、测试或验收记录。
- 没有值得单独提醒的变化时，可以只写「优化使用体验，修复已知问题」。不声称尚未实现的功能或未经确认的效果。
- `CHANGELOG.md` 继续完整记录实际改动及验证情况，无需为了手机展示而删减。摘要仅覆盖本次安装包实际包含的变化。
- 发布工具同时检查对应 CHANGELOG 版本章节与摘要文件，摘要缺失、版本不符或过长会阻止发布材料写入；不自动截断或从工程日志抽取首句。

签名清单仍使用 `notes` 字符串，每条摘要占一行，兼容旧客户端。新客户端遇到历史长说明时显示通用短句，不显示被截断的技术流水账。
