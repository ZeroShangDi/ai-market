# 待办 issue：资源转链接与统一管理通用能力

日期：2026-10-14

状态：通用 CLI、登记清单、存储适配与移动端名称解析/回退已准备，两个页面的应用图标已接入可选资源引用；真实云上传、域名部署与图形管理界面待后续。未开通云服务或配置真实上传凭据。实现和验证见 [移动入口交付记录](../reviews/2026-10-14-mobile-entry-implementation.md)。

## 定位与要求

作为非业务的项目通用能力，统一管理原图、派生图片与所有生成的访问链接。外部系统和业务页面只引用资源，不依赖具体 CDN 或存储供应商。

- 支持命令行及程序上传，AI 可以直接执行，不要求每次手工操作控制台。
- 原图保留并纳入资源库，压缩图、缩略图等作为派生版本登记。
- 后续切换 CDN 或存储服务时，保持外部资源标识及访问地址稳定。

## 已讨论的方案

- 复用后端现有文件管理、上传接口和 S3 存储适配，扩展独立资源登记与解析能力。
- 资源记录包含资源 ID、名称、分类、原图位置、内容哈希、格式、尺寸、版本、派生图、存储配置和访问地址。
- 使用项目自有资源域名及稳定路径，避免将供应商 URL 作为资源的唯一身份。
- 页面通过资源名称或稳定链接引用；存储、CDN 和供应商参数集中管理。
- Cloudflare R2 + 自有域名是当前候选方案，尚未开通或完成适配验证。最终供应商需结合实际网络访问、成本与配置确定。
- 上传入口统一完成：读取文件 → 计算哈希 → 上传原图 → 生成并上传派生图 → 登记资源 → 返回稳定链接。派生图策略按资源类型决定，不强制转换 SVG、动画等资源。
- 程序上传也必须登记，不能只上传对象而遗漏资源库记录。命令名称与接口尚未实现或定稿。
- 首次配置账号、存储桶、域名和运行环境凭据后，后续上传、批量导入及查询可由程序完成；客户端仅获得资源引用，不携带上传凭据。

## 访问与离线边界

- 若图片仅存于后端所在机器，并通过该机器提供访问，客户端与该地址断开连接后无法重新加载图片。已缓存资源是否可见取决于本地缓存实现。
- 使用云存储/CDN 直链，且该链接不要求实时请求业务后端才能获得访问权限时，图片访问可独立于业务后端；仍需要网络。
- 需要后端解析、动态鉴权或签名的资源，不能据此承诺后端不可达时仍可加载。
- 完全断网时，只有随应用打包或已缓存的资源能够使用。因此资源库、存储位置和离线缓存需分别设计。

## 现有基础与差距

现有文件管理已记录文件名、路径、存储配置、URL、类型和大小，提供上传及预签名上传接口。但上传接口直接返回存储地址；稳定资源身份、原图与派生图关系、迁移映射和统一上传命令仍需完善。

## 待确认与验收

- 明确资源库是仅供运行期使用，还是也服务于开发期静态资源；明确后端不可达时上传登记的行为，不静默丢失记录。
- 确定公开 UI 图片与需要权限的业务资源的访问及缓存策略。
- 设计去重、版本管理、原图备份、上传失败恢复及原图与派生图关联。
- 切换 CDN 时验证缓存与地址稳定性；切换存储时迁移原图和派生图、校验内容，再切换映射，保留回退能力。
- 命令或程序可以完成上传与登记，返回稳定链接；资源库可以检索原图、派生图和链接。
- 同一原图能够追踪所有派生版本；已有外部引用无需因更换供应商而逐个修改。
- 验证后端不可达、图片服务不可达、完全断网三种情况，并明确本地占位和缓存行为。
