# 待办 issue：可扩展 AI 助手与首条任务执行链路

日期：2026-10-14

状态：首期原型、离线验证及真实 DeepSeek 模型任务联调已完成，使用 Claude Agent SDK 执行循环与 DeepSeek 官方兼容接口。实际客户数据库与真机联合验收仍待完成，本文不代表完整链路已经上线。

## 目标与产品形态

最大限度复用非业务的通用 AI 能力，保持框架可持续优化。先跑通一条完整链路，再逐步增加文件类型、语音、技能、专家、MCP 和连接器。

移动端以 AI 对话为主要工作入口，进度、结果、确认与补充信息尽量在对话中完成。应用广场提供能力启用和配置入口；不因新增一种能力就新增独立业务页面。

## 首期验收目标（用户已确认）

用户在手机上传资料或说一句话，助手读取资料、查询已授权数据、生成一个可下载结果；需要写入业务时在对话里询问，用户离开页面后任务仍继续，完成后回来汇报。

用户随后已授权“做做试试，能并行开发的就并行开发”。本轮选定文字指令、UTF-8 TXT/Markdown 输入、授权客户快照查询、Markdown 跟进报告与用户确认后的跟进待办写入；语音转文字后续接入。

- 手机可以发起任务，显示关联的输入资料和当前状态。
- 助手能够使用一个技能/专家配置，读取一种资料并调用一个真实、已授权的查询能力；不以模拟响应冒充真实完成。
- 最终产生可下载、可验证内容的文件，文件归属和访问权限明确。
- 写入业务前在对话中展示操作对象和内容；确认绑定具体任务与参数，后端重新校验权限，重复确认不重复写入。
- 用户离开对话页面后，已交办任务继续；返回后能看到状态与结果，完成结果能够汇报给用户。首期汇报渠道在实施时明确，不默认承诺系统推送已接入。
- 失败、取消和等待用户都有明确状态，不能仅靠一段自然语言声称任务已完成。
- 通过新增第二个技能或工具验证扩展边界，避免每次新增能力都修改聊天、任务及业务基础代码。

## 已确认的架构原则

1. 平台任务记录独立于 SDK 会话。平台保存交办人、任务状态、专家/技能版本、产物引用和结果，SDK 会话 ID 仅作关联。更换引擎不应要求重建产品数据模型。
2. 简单聊天和复杂任务分别执行。现有模型接口可继续承接普通问答，文件处理、多工具执行和产物生成可进入 Agent 执行服务；首期不建设庞大多引擎框架。
3. 业务能力与引擎分开。领域模块拥有规则和用例，工具/MCP 适配复用用例，Skill 描述工作方法，专家组合技能、工具和输出要求；SDK 类型不进入领域契约。
4. 优先复用成熟的执行引擎、文件处理工具、语音服务及公开/开源连接器，平台掌握任务、权限、业务规则、专家定义和产物。先验证一个执行引擎，保留可替换边界。
5. 能力质量逐步优化，框架正确性通过真实链路和扩展验证判断，不以抽象设计或目录结构直接宣称已经保证。

## SDK 与产品能力的边界

Claude Agent SDK 作为首期重点验证候选，Codex 可作后续对照；DeepSeek 相关 Agent SDK 暂不重点考虑。

SDK 可复用执行循环、上下文管理和工具扩展等基础能力，但不直接交付完整 CLI/桌面产品。平台仍需要任务生命周期、移动端交互、文件上传与下载、产物展示、连接授权、执行环境及验证。

应接受这一产品层差距和工程投入，通过复用减少重复实现；不承诺接入 SDK 后自动获得完整桌面体验。SDK 与工具链的能力、认证、许可和实际运行结果在实施时核验并锁定版本。

## 连接器首期范围

- 优先使用开放、公开或开源的连接器，同时主要维护本项目自身的连接器；不提前全面自研第三方系统接入。
- 自有连接器复用已有业务接口和授权上下文，不复制领域规则，不让模型自报身份决定数据范围。
- 外部连接器按实际需要接入，核验许可证、工具范围、配置依赖和运行位置；公开可获取不等于无需账号授权。
- 连接器管理账号与凭据生命周期，MCP 是工具通信方式之一，二者不等同。

## 后续问题清单与触发时机

下列问题已记录，首期不一次性建设完整解决体系。已被首条链路触及的最小正确性必须实现。

| 问题 | 后续展开时机 | 首期边界 |
|---|---|---|
| 长任务恢复与重复副作用 | 引入重启恢复、自动重试或跨系统写入 | 离开页面后继续执行属于首期；重启中断需明确失败，不能无条件重放写入 |
| 用户电脑执行、设备授权与断线恢复 | 需要本地文件或本地应用操作时 | 先在受控服务端工作区执行，不承诺可操作用户电脑 |
| 多租户执行环境隔离 | 面向多个真实租户/用户开放 Agent 时 | 原型可限定单用户；沿用身份校验，文件和凭据不能共享越权，多租户开放前补齐执行隔离 |
| 第三方连接器授权、限流、同步和恢复 | 增加相应外部系统时 | 优先自有查询与必要的开放连接器，接入一个就验证一个 |
| 自主执行成本与质量波动 | 工具和任务数量增加时 | 设置基础超时/轮数边界，核验产物；高级配额、调度和评测逐步完善 |
| 多格式 Office 保真与专业产物 | 扩展文件处理范围时 | 先选一种输入和一种输出，验证可读性与内容 |
| 多专家协作、长期记忆和任务交接 | 单专家链路稳定后 | 首期专家采用配置，避免过早引入复杂协作 |
| 实时双向语音与宠物唤醒 | 基础对话与任务链路稳定后 | 见独立实时语音 issue；语音转文字可先接入 |

## 当前基础与差距

现有普通 AI 会话具备历史、流式输出、取消、重新生成、请求幂等和身份隔离，继续沿用。新增 Agent 资料任务具有独立协议与持久化，离开页面只暂停观察；服务重启后执行中任务明确失败，不自动重放。当前实现状态、测试证据和未完成项见接力记录，不能以离线替身验证代替真实模型与业务验收。
