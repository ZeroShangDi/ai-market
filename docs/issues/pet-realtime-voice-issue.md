# 待办 issue：实时语音与桌宠对话入口

日期：2026-10-14

状态：后置规划，暂不实施。用户倾向将实时语音主要放在桌宠入口，最终入口与交互尚未定稿。

## 目标

桌宠作为助手的便捷沟通入口，后续支持实时双向语音，可交代任务、听取结果，并处理任务需要用户决定的问题。复用平台会话、任务与能力层，不另建独立的 Agent 或业务逻辑。

## 阶段关系

- 优先跑通 [AI 助手首条任务链路](ai-agent-capability-roadmap-issue.md)。
- 按住说话、语音转文字后发送可先接入；这不代表已支持实时双向语音。
- 实时语音后置，初步考虑作为桌宠能力。持续监听、关键词唤醒和后台常驻不是本次已确认需求，需要分别评估。

## 后续设计与验证项

- 确定首个目标平台，以及 App 内桌宠、悬浮窗或桌面桌宠的实际入口。
- 麦克风授权、连接/断开、语音识别与播报、用户打断、弱网与重连、音频焦点和通话冲突。
- 区分结束语音会话、取消任务和暂停等待，避免用户关闭语音就误取消后台任务。
- 语音交办与文字交办进入同一任务协议；关键业务写入仍可展示可复核的确认内容。
- 原始录音是否保存、保存范围与期限需明确，不默认长期保存全部语音。
- 如需锁屏、后台或唤醒，单独验证平台限制、耗电和权限；不提前承诺跨平台常驻。

## 后续验收方向

能从桌宠入口开始和结束实时对话，能打断播报并继续交流；交办的任务可在原对话查询，结果与需决策事项能回到相同助手上下文。具体延迟与识别质量指标在选定服务和目标设备后制定。
