# 待办 issue：统一图标管理通用能力

日期：2026-10-14

状态：基础能力已实现并接入移动端工作台、应用广场与底栏；PC 全量迁移、其他渲染平台适配及可视化管理待后续。实现和验证见 [移动入口交付记录](../reviews/2026-10-14-mobile-entry-implementation.md)。

## 定位与要求

作为项目通用能力，供 PC、uni 移动端及后续应用使用，不属于拨号、客户管理等具体业务。

- 图标统一管理，默认资源覆盖大多数需求，业务页面通常无需逐个导入图标或另外寻找资源。
- 支持按统一方式额外导入 SVG、PNG 等自定义资源。
- 同时支持单色图标、品牌色图标和必要的多色图标，例如微信图标默认保留品牌配色。

## 已讨论的方案

- 使用 Iconify 作为资源组织入口，Remix Icon 作为默认图标风格；品牌图标与自定义图标作为补充集合。
- 建立共享图标注册表，统一登记语义名称、资源来源、默认尺寸、配色策略和替代资源。
- 页面通过统一图标组件和语义名称调用，例如 search、phone、wechat，不直接依赖文件路径或具体图库名称。
- 明确区分随主题变色与保留原色，避免品牌及多色图标被统一染色。
- PC 与 uni 移动端共享资源定义，各自适配渲染方式；不能直接将 PC 的 @iconify/vue 当作 uni 跨端实现。
- 构建时按实际使用收集资源，避免整库进入安装包；核心图标随应用打包，不依赖后端或公共图标 API 的实时访问。

## 现有基础

PC 已有 Iconify 与本地 SVG 封装；移动端已有 TDesign 图标和零散静态 SVG。实施前需核对这些入口的兼容与迁移方式。

## 待确认与验收

- 确定 uni 支持的平台及各平台 SVG、图片或其他渲染适配方式。
- 确定动态图标名称的收集规则，避免运行时引用遗漏。
- 明确注册、预览、命名、缺失图标回退及图库版本管理方式，并保留各来源的许可信息。
- 两端使用同一语义名称获得一致图形；微信等品牌图标正确保留颜色。
- 新增自定义图标不要求修改业务页面的组件调用方式。
- 常用图标在断网或业务后端不可达时仍可显示，构建产物只包含所需资源。
