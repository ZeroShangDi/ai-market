# 项目开发规则

## 适用范围

本文件统一维护新架构开发规则。当前逻辑根为 `next/`，业务模块提供给使用者的 AI 技能随模块维护，与本开发规则分开。这里定义的是规范，不表示对应自动检查、注册器或生成工具已经实现。

## 工作范围

本分支所有文件改动严格限定在 `next/` 内，包括源码、文档、配置、脚本、资源、生成文件及依赖锁文件。不得新增、修改、删除、移动或格式化 `next/` 外的任何文件，也不得顺手修复或回滚外部已有改动。可只读检查旧工程以分析和复用。执行安装、构建、测试或代码生成前，确认工作目录、输出与缓存位置不会写到 `next/` 外；无法满足时停止该操作并说明原因。

## 创建前先查找并复用已有实现

新增实现前先查找已有实现；能安全增量扩展时优先复用。必须破坏性修改时，先核对使用范围并评估影响，影响较大时先确认。模块边界先分析业务规则、事务和数据归属，不按菜单直接划分。

## 目录与文档组织

应用归 `applications`，运行工程归 `containers`，领域实现归 `modules`，共享资源归 `packages`，运维归 `devops`。`containers` 按实际可运行工程组织，不固定工程数量、框架或语言，同一用途允许不同实现并存或替换。模块通过稳定契约与工程交互，不依赖框架工程内部实现。

项目级文档按用途在 `docs/` 内归类；模块与包的接口、接入和实现说明可随对应目录维护。开发规则只维护本文件，不另设入口文件或重复正文。

## 路径与迁移

路径相对逻辑根组织，不在运行、构建或配置中硬编码仓库绝对路径或临时目录名前缀。当前分支以隔离建设为范围，整体迁至仓库根属于后续单独授权的工作；完整迁移约定见 [迁移说明](../migration.md)。

## 顶层职责与交付标准

| 目录 | 职责 | 输入 | 输出 | 边界与检查点 |
|---|---|---|---|---|
| `applications` | 将领域能力组合成产品；跨模块页面、用例、流程、角色映射、扩展绑定 | 模块公开契约、入口能力、应用配置 | 应用定义、各端组合入口、流程与扩展注册 | 不拥有模块业务表、不重写领域规则、不直接访问数据库；应用间不导入实现 |
| `containers` | 可运行工程；启动、基础设施、宿主生命周期、依赖注入、协议接入与装配 | 应用入口、模块公开入口、基础包、环境配置和凭据引用 | 可运行前后端制品、健康状态、受控宿主能力 | 框架与工程数量不限；工程装配可引用模块公开入口，但基础设施内部不得出现具体业务分支 |
| `packages` | 有明确复用需求的通用代码、资源、接口、技术适配 | 通用配置、显式参数或端口 | 独立声明依赖的包及公开出口 | 不依赖具体模块/应用/工程；领域 DTO 不因被多处使用就搬到此目录；不设万能 common |
| `modules` | 拥有领域规则、状态、数据和对外能力，按需交付多端实现、AI 能力与连接器 | 显式业务输入、调用上下文、领域依赖与基础端口 | 版本化命令/查询/事件、前端贡献、AI 工具及技能、适配器 | 不依赖应用或工程内部实现，不跨域读写表，不暴露 ORM 和可变内部状态 |
| `docs` | 业务与架构说明、决策、接口使用、运行和迁移记录 | 已确认需求、规则、源码事实、验证结果 | 可追溯文档，区分现状/目标/建议 | 不能宣称未验证能力已完成；规范原文统一放 docs/rules，其他文档引用而非复制 |
| `docs/rules` | AI 开发约束、目录边界、协议标准、检查清单 | 用户已确认决策、架构约束 | 可执行的开发要求与例外约定 | 开发规范与业务 SKILL 分开；变更约束时说明影响，不静默放宽 |
| `devops` | 构建、契约检查、发布、部署、升级、备份恢复和运维 | 工程与应用定义、版本锁定、迁移清单、环境配置 | 制品、部署计划、发布记录、验证/回退结果 | 不写业务规则；迁移脚本归数据所有者，devops 只编排执行；不保存真实凭据 |

依赖注入发生在工程装配处；业务组合的实现放 applications。不能因为装配处能引用所有对象，就把业务流程搬进 containers。

## 允许的源码依赖

| 使用方 | 允许引用 | 禁止引用 |
|---|---|---|
| applications | modules 的公开出口、packages 公共接口、自身组合 | containers 内部、其他应用实现、模块内部路径、领域存储实现 |
| containers 装配层 | applications 入口、modules 公开注册/提供者入口、packages | 通过私有路径绕过模块公开面 |
| containers 基础设施 | packages、工程自身技术实现 | 领域状态和规则；业务调用由装配后的模块执行 |
| modules | 自身实现、packages、显式声明的其他模块公开契约 | applications、containers、他域内部实体/服务/表 |
| packages | 其他基础包公开出口和第三方库 | modules、applications、containers |
| devops | 构建与部署描述、版本清单 | 被业务运行时代码反向导入；直接实现业务数据变更 |

源码依赖图应无环。运行时调用不要求绝对无回路，但不得同步互调形成递归/死锁；事件因果链须防止自触发循环。进程内调用与远程调用共享业务契约，但超时、事务和身份传播必须分别声明，不声称二者完全等价。

领域间稳定的业务依赖允许通过公开契约表达；仅用于某个应用的联系通过应用组合建立。模块可以定义自己需要的端口，再由应用/工程装配绑定实现，不能为消除循环随意搬接口到 packages。

## 模块内部职责

下列是责任分类，可按实际技术调整目录；不要求全部具备。

| 部分 | 拥有的内容 | 对外边界 |
|---|---|---|
| contracts | 本领域公开命令、查询、事件、数据 schema | 由领域所有者维护，尽量不依赖框架和实现 |
| backend/domain | 实体、值对象、状态规则、不变量 | 不依赖 HTTP、ORM、UI、MCP 或具体外部 SDK |
| backend/application | 用例、授权调用、事务要求、所需端口 | 对外业务操作的单一实现，所有入站适配复用 |
| backend/adapters | HTTP、持久化、事件传输等协议实现 | 依赖内层端口；由公开提供者入口供工程装配，不开放内部 Mapper |
| web/mobile 等前端类型 | 本领域页面、组件、交互控制器、查询和状态视图 | 公开页面/组件/工厂，私有 store 与路由实现不外泄 |
| AI 能力 | 工具适配、技能、提示模板等 | 复用领域用例，声明工具/宿主依赖；技能文本不构成授权 |
| connectors | 外部对象到本领域的映射、同步语义、入站/出站适配 | 不把外部数据模型传进领域；入站仍调用用例 |
| migrations | 本领域数据结构升级 | 声明前置版本、数据影响及回退限制 |
| tests | 不变量、契约、适配、隔离和失败行为验证 | 测试替身走同一端口，不冒充真实集成验证 |

AI 资源可以组织为 `ai/skills`、`ai/mcp`，也可保留模块已有的 `skills`、`mcp` 目录；以清单显式定位。新增类型遵循扩展协议，不靠约定扫描任意文件自动执行。

## 公共基础能力放在哪里

只用于一个工程的基础实现可以留在 containers。已出现稳定复用需求时提取 packages。业务专属的外部协议映射留在模块 connectors/adapters；通用 HTTP、凭据管理、安全存储可以共享。

数据所有权由业务决定：文件介质可由平台提供，录音归属和读取授权仍属于通信；身份认证可以共享，客户是否允许联系仍由客户所属领域决定。

## 模块公开描述

每个实际模块必须提供人和工具可定位的公开描述，至少列明：

- 稳定 ID、模块版本、责任范围和数据所有权。
- 导出的能力 ID、种类、契约版本、输入/输出 schema 与错误语义。
- 所需的模块能力、宿主能力、第三方包及兼容范围；区分必需/可选。
- 按后端、Web、移动、AI 等目标列出公开入口和制品/运行要求。
- 权限、数据范围、外部资源及副作用声明；扩展点引用。
- 初始化、停用和释放行为；缺失可选能力的降级方式。

发布时由 devops 记录解析后的确切版本和制品摘要；开发期兼容范围不等于生产运行时随意追最新版本。入口是导入白名单，不接受配置中任意代码路径、表达式或未经注册的 URL。

每个技术目标有独立公开出口，代码入口统一命名为 `main`（如 `main.ts`、`main.py`），包 exports 指向该入口；HTTP schema、MCP 工具另按契约声明。模块或包根目录不把所有实现一股脑 re-export。公开 DTO 由 contracts 定义，禁止输出 ORM、内部 service、数据库连接或原始密钥。

核心方法必须具备文档注释：JS/TS 使用 JSDoc，Python 使用对应的 docstring，说明参数、返回、失败与副作用；复杂的并发、取消、队列和资源释放逻辑应注释说明约束及原因。

模块与包的核心实现统一放在 `src/`，公开入口直接使用 `src/main.ts` 或 `src/main.py`，不再为入口增加一层同名包目录。Python 通过构建配置映射导入包名。文档、测试和构建配置留在各自目录，不与核心实现混放。

## 各种公开输出

| 类型 | 允许的输出 | 必须明确 |
|---|---|---|
| 后端命令 | 确认结果、资源引用、版本或异步任务 ID | 权限、状态前置、幂等、并发、事务、副作用、错误 |
| 后端查询 | 只读 DTO、分页结果、聚合视图 | 数据范围、过滤、分页、排序、时间与一致性口径 |
| 纯函数 | 明确类型的值 | 是否纯函数、异常、确定性；不强加网络响应信封 |
| 有副作用的函数/控制器方法 | Promise/结果类型或任务句柄 | 完成的含义、超时/取消、重试、错误和执行身份 |
| 事件 | 已发生的领域事实及最小必要引用 | 版本、事件 ID、租户、时间、关联/因果 ID、聚合版本和交付语义 |
| 页面/组件 | 页面贡献描述、组件公开 props/events/slots | 目标框架/平台、路由相对前缀、权限、挂载/卸载、样式作用域 |
| 前端状态 | 实例范围的只读快照、selector、订阅、受控 actions | 身份与应用实例范围、状态来源、清理、刷新、错误和一致性 |
| MCP 等 AI 工具 | 工具 schema、权限声明、适配处理入口 | 复用哪个用例、调用身份、副作用、确认需求、限额和错误映射 |
| SKILL/提示资源 | 版本化文本、资源引用和所需工具声明 | 适用范围、前置条件、兼容工具版本；文本不得携带凭据 |
| 连接器 | 配置 schema、能力声明和提供者工厂 | 凭据引用、权限范围、外部模型映射、游标/去重/恢复、释放 |

前端可导出方法和状态，但不导出任意可写的全局 store。推荐由工厂创建应用/会话范围的实例：查询读快照，操作走 action，订阅返回取消订阅函数。模块不得修改其他模块的状态；跨页面共享必须明确实例作用域。

框架组件可以公开，但要标注框架及版本。框架无关的业务契约和控制器与 Vue/React 等视图适配分开，不承诺一个组件文件可直接用于所有框架。

## 操作输入与上下文

业务输入与执行上下文分开。上下文按需携带调用者、租户、应用实例、关联 ID、时限和取消信号；不能把用户提交的 tenant/user/role 字段当成可信身份。后端从认证信息建立上下文；服务间调用保留原调用者或显式服务身份及授权范围。

输入跨信任边界必须校验 schema 和大小；内部公开契约应有类型和前置条件。额外字段如何处理需明确，不允许把任意对象透传至数据库或外部 SDK。

有重复外部动作或持久化写入风险的命令必须定义幂等：键作用域、同键同请求结果、不同请求冲突、并发重放、保留窗口。涉及并发修改的操作声明期望版本/冲突策略。纯函数和只读查询不机械添加幂等键。

当前项目沿用十进制字符串表示长整型 ID；对外时间使用 ISO 8601 并明确时区，时长附单位。货币、枚举、分页和空值语义需在各契约中明确，不输出不受约束的 `any`。

## 成功、失败与生命周期

- “完成”须说明是本地提交、持久化排队、远端确认还是外部动作完成。长任务返回任务引用和可查询状态，不能先返回成功后静默失败。
- 错误区分输入、无权限、状态冲突、不可用、暂时失败和结果不确定；用稳定错误码，日志诊断与用户信息分开，不泄漏堆栈和敏感数据。
- 取消等待不等于取消已发生的外部动作。超时后不得无条件重试拨号/发消息等行为，应按请求 ID 查询或对账。
- 传输层可将用例错误映射为 HTTP/MCP 格式，但不能改变业务结果。保留现有 API 兼容适配直至消费者迁移完成。
- 每个有资源的公开对象定义 dispose/unmount：清理监听器、计时器、网络流与任务引用。切换身份/租户必须隔离状态和未完成任务，不允许跨身份恢复。

## 应用、工程、资源包的输出

应用输出选用能力、各端组合入口、流程定义版本、角色映射、配置 schema 和扩展绑定；不携带环境密钥。工程输出可运行制品及其兼容能力列表。资源包输出受控 exports 和依赖声明。发布制品应可定位回源码版本、配置版本与迁移集。

模块版本、契约版本、数据迁移版本、流程版本分别管理。新增枚举值也可能破坏消费者；兼容性按实际语义判断，不能只按是否删除字段判断。进行中流程绑定原版本，升级策略必须说明继续、迁移或终止的行为。

## 外部依赖的准入与封装

不是每个第三方函数都需要包装。按依赖的副作用、可替换性、信任边界和业务影响选择方式。

| 依赖 | 可以怎样使用 | 必须隔离的部分 |
|---|---|---|
| 稳定纯计算/格式化库 | 可在合适层直接依赖，声明并锁定版本 | 不向公开契约泄漏第三方专用类型；若库引入 I/O 或全局状态，重新评估 |
| Vue、Spring、ORM 等框架 | 放相应 UI/应用装配/适配层 | 领域模型和跨模块契约不依赖框架内部对象 |
| 数据库、文件、缓存、消息、时钟、随机数 | 用所需端口访问，由工程注入适配 | 业务数据归属、可测试的时间/随机行为、事务与资源释放 |
| 第三方 API、模型服务、外部 MCP | 用模块所需能力端口和出站适配/连接器 | 凭据、超时、限流、错误、外部 schema、重试与结果不确定性 |
| 原生系统、浏览器与桌面能力 | 用宿主能力接口，工程提供实现 | 权限、平台支持、生命周期；模块不直接调用任意文件/IPC |
| 另一个业务模块 | 依赖公开能力，或声明所需端口再绑定 | 禁止深层导入、共享表访问和传递私有实体 |
| 外部前端资源/不可信扩展 | 受控来源、版本化制品、明确加载方式 | 不可信代码不作为同权限同源模块运行；用隔离进程/独立源等边界与受限能力代理 |

端口由需求方定义业务所需能力；提供方的技术复杂度留在适配器中。只有确实普适且稳定的接口才进入 packages，不能要求所有领域使用万能 HTTP/AI/数据库业务接口。

业务模块不得自行到全局容器查找服务，也不直接读宿主私有配置或凭据。工程装配传入已校验配置和受限能力。服务端凭据通过引用绑定；前端和 SKILL 中不保存服务端长期凭据。日志记录关联信息，不默认记录号码、录音、提示内容或密钥。

## 外部扩展的统一部分

统一的是扩展的“描述、校验、绑定、生命周期”，不是把所有类型改成一个 `execute(any)`。

每个扩展点至少定义：稳定命名空间 ID、类型、契约版本、输入/输出 schema、允许的执行位置、必需能力/权限、一个还是多个实现、执行时机、顺序或竞争规则、同步/异步、超时/取消、错误处理及卸载方式。

扩展实现声明扩展点 ID、兼容版本、实现版本及入口、配置 schema、资源依赖、权限和信任等级。由应用选择绑定，由工程装配校验并实例化；模块不能自动扫描并执行未知代码。

必需扩展缺失或不兼容时拒绝启动相应能力；可选扩展缺失按明确策略降级。未知类型不执行；必需类型拒绝装配，可选类型跳过并留下可查询诊断。不能把“可选”当作静默忽略所有故障。

第一版可使用静态注册表与类型化配置，不要求运行时插件市场、动态下载或通用引擎。

## 不同需求的扩展方式

| 需求 | 使用机制 | 规则 |
|---|---|---|
| 替换拨号提供者、存储或模型 | 端口 + 适配器注入 | 一个明确提供者，或显式路由策略；校验能力和配置 |
| 操作前判断是否允许 | 必需规则留领域；可选产品策略通过声明的 policy 接口 | 策略不能跳过租户/权限/状态不变量，禁止任意 before 钩子篡改实体 |
| 操作结果影响下一步且需返回整体结果 | 应用用例组合 | 明确顺序、失败、事务和幂等；函数返回值可直接组合，无需另造钩子 |
| 同事务完成多个模块的业务操作 | 应用协调公开用例 + 显式工作单元 | 只在同进程且参与同一事务资源时承诺；事务传播由适配实现并验证 |
| 业务提交后必须执行后续工作 | 持久事件 + 可恢复消费者/流程 | 同事务写 Outbox，至少一次投递、去重、重试与失败记录；不使用内存回调保证必达 |
| 仅更新界面、显示提示或可丢失观察 | 类型化回调/订阅 | 标注非持久；错误与业务提交隔离；订阅须可释放 |
| 扩展详情页按钮、卡片、页签 | 具名 UI 插槽/贡献点 | 明确上下文、权限、目标框架、排序与冲突规则，禁止任意改宿主 DOM/router |
| 增加 MCP 工具/技能/未来 AI 类型 | 按类型的能力提供者 | 校验 schema 与权限；调用统一用例，资源文本不授予能力 |

一个成功后发生的动作到底用回调还是事件，由可靠性和事务语义决定，与入口是 HTTP 还是导出的函数无关。

## 通话结束示例：三个不同的时刻

1. 原生设备观察到挂断：可能重复、延迟或缺失，只是技术观察；供通信模块判断，不等于业务结果已经提交。
2. 通信模块的“完成通话”用例提交成功：形成业务事实，可发布版本化完成事件。
3. 某应用的“保存外呼结果并建立跟进”整体提交成功：才表示这个跨模块用例完成。

若当前产品要求通话与跟进同成同败，应用通过工作单元调用两个公开操作，沿用本地事务。领域模块不能提前提交，事件由最外层事务成功后才可见。外部拨号/消息不能参加数据库回滚，不应放在长事务中假装可撤销。

若产品允许跟进延迟，则在通话事务内写入完成事件的 Outbox，应用消费者按事件 ID/业务键去重创建跟进，并展示待处理/失败状态。这是产品行为变化，需要显式决策。

仅用于 UI 的导出函数可以这样使用（示意，不是已实现 API）：

```ts
const result = await communication.completeCall(input)
// 此处只更新界面，不承担必须成功的业务副作用。
view.showSaved(result.callId)
```

需要多处观察 UI 状态时，可公开 `subscribe(listener): () => void`。不强制每个方法都有 `before/after/onSuccess`。若提供钩子，必须说明它发生在提交前还是提交后、是否 await、超时和异常是否影响调用结果；默认禁止用可选 UI 钩子决定事务成败。

## 前端状态与 UI 扩展

对外可提供页面、组件、纯函数、命令方法、只读状态与订阅。实例按用户/租户/应用范围建立；不得把可变单例 store 作为公共协议。UI 临时状态与服务端业务状态分开，前端成功提示不能作为服务端已提交的证据。

贡献点定义具体上下文，例如只提供对象引用和已脱敏摘要，不把完整宿主 store、令牌或数据库代理交给扩展。相同 ID 重复注册应报错；多贡献按显式排序和稳定次序展示；单提供者冲突必须拒绝或按声明选择，不能“最后注册覆盖”。

卸载、登出与租户切换要取消订阅并隔离进行中的响应。停用模块先阻止新工作，再按策略收尾/取消旧工作；卸载不自动删除数据。

## 新增类型如何接入

未来出现新的端类型或 AI 资源类型时：

1. 描述实际消费者、输入输出、信任边界与生命周期，先确认已有类型能否表达。
2. 定义新的类型 schema 与处理适配，不修改已有类型的语义。
3. 工程声明支持的类型和契约版本；模块声明需要哪些类型及其必需性。
4. 应用显式选择与绑定，构建/启动检查兼容性，未知类型按“外部扩展的统一部分”处理。
5. 提供成功、不可用、拒绝、失败和清理的契约测试。

为未来保留扩展位置，不提前实现没有消费者的通用类型系统。

## 开发前

- 明确本次属于哪个目录、哪个数据/规则所有者；跨模块工作明确应用协调者。
- 查找已有实现、公开接口和规范，先判断复用与增量扩展，避免复制。
- 列出输入、输出、失败行为、必需/可选依赖、外部副作用和执行身份。
- 需要扩展点时，先用真实消费者证明需求；优先函数组合或端口，不默认新增插件框架。
- 所有文件改动、命令输出、缓存、依赖安装和测试制品仅在当前临时根内。不能为清理工作区而回滚外部已有改动。

## 按目录检查

| 位置 | 最少检查 |
|---|---|
| applications | 是否只通过公开能力组合；应用特有流程有明确归属；事务/异步与失败行为是否描述；不同应用是否意外共享状态 |
| containers | 是否只承担运行和基础机制；模块是否通过注入拿能力；框架私有类型是否泄漏；版本与能力不匹配是否早期失败 |
| packages | 是否存在真实复用需求；是否反向依赖业务；是否把领域 DTO/业务组件错误归为通用；公开出口是否最小 |
| modules | 数据唯一所有者、无跨域表访问、无私有导入；公开入口有契约；所有输入适配是否复用同一用例与授权 |
| docs | 现状/目标/建议区分；事实有源码/验证依据；与规范链接一致 |
| docs/rules | 新约束是否有适用范围和检查方式；是否与用户决策或其他规则冲突；是否引入无需求的审批流程 |
| devops | 版本/制品可追溯；迁移由正确所有者执行；凭据不入库；输出路径、失败与回退措施明确 |

## 按公开能力检查

| 类型 | 契约验证重点 |
|---|---|
| 命令/副作用函数 | 输入校验、权限、状态前置、幂等重放/冲突、并发、提交定义、结果不确定时的核对 |
| 查询/纯函数 | 数据范围、边界输入、单位/时间、分页一致性、错误与空值 |
| 状态/订阅 | 实例隔离、只读、取消订阅、登出/租户切换后旧响应不污染新状态 |
| 页面/组件 | props/events/slots、深链接、权限展示、样式隔离、挂载失败、卸载资源释放 |
| 事件/消费者 | 提交后可见、重复/乱序/延迟、消费者崩溃、重试/重放、去重保留周期、死循环防护 |
| 端口/连接器 | 不支持能力、外部超时/限流/错误映射、凭据隔离、映射、游标与取消、真实集成证据 |
| 扩展点/提供者 | 缺失/不兼容、重复 ID、多提供者冲突、顺序、失败影响、停用/卸载 |
| AI 工具/技能 | 输入 schema、用户/服务身份、授权范围、调用统一用例；不把模型输出当可信指令或数据库输入 |

测试按风险选取。文档或占位目录不写镜像测试；纯计算可单测；有事务和幂等语义的用例必须验证真实持久化边界。原生拨号、设备后台能力和外部服务不能仅凭 mock 通过就视为真实可用。

## 事务与可靠性

明确最外层事务、跨模块传播、提交后事件、外部副作用边界。跨进程不继承本地事务语义。

## 身份与隔离

区分用户、租户、应用安装和模块实例；应用 ID 不自动成为数据隔离边界。后台工作保留授权范围，不能无限继承旧权限。

## 状态与流程恢复

明确持久化位置、重试窗口、身份切换、服务重启、任务取消、停用后的收尾。

## 版本与兼容

模块/接口/事件/流程/数据版本分开；新增字段或枚举按语义验证；旧消费者有兼容窗口。

## 可观测性

用关联 ID 串起命令、事件与外部调用；区分业务拒绝、技术失败和结果不确定。暴露必要健康状态，避免日志含敏感正文。

## 时间与顺序

区分发生时间与接收时间，声明时区；不能仅靠时间戳保证全局顺序，必要时使用聚合版本。

## 配置与凭据

schema 校验、作用范围、缺省值、配置更新生效时间；凭据独立注入和轮换。

## 资源与性能

外部调用有时限、并发/队列上限和失败处理；不要无限重试或允许扩展无限占用宿主资源。

## 数据与迁移

每张表唯一写入者；迁移前置条件、兼容发布顺序、备份恢复；代码回退不等于数据可逆。

## 扩展信任

自有受信任扩展与第三方不可信代码分开处理；静态类型不能替代运行隔离和权限校验。

## 演进与下线

扩展/模块废弃需清点消费者、进行中流程和数据；卸载不等于删除。

## 构建可移植性

不硬编码临时目录名；锁定第三方依赖与可重现制品；记录必要许可证/使用限制，按实际依赖核验。

## 每次新增公开能力的交付记录

在模块/应用自身文档中提供以下内容，可用简表，不强制另造文件：

1. 所有者、用途与公开入口。
2. 输入/输出及成功的准确含义。
3. 依赖、执行身份、权限和外部资源。
4. 幂等/事务/事件/回调选择及失败处理。
5. 兼容版本、生命周期、停用与资源释放。
6. 已验证场景、验证方式及仍未验证的部分。

例外不得静默突破边界：先说明必要性、影响和退出条件，保留记录。涉及当前用户明确的写入范围限制时不能自行例外。
