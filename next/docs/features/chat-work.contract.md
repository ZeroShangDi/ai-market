# 聊天与工作接入边界

## 当前契约

| 项目 | 约定 |
|---|---|
| 聊天包 | [chat](../../packages/chat/README.md)：工厂 + 六个方法；生成器、插件、配置、存储由外部注入 |
| 工作包 | [work](../../packages/work/README.md)：工厂 + 八个方法；mode 选择 OpenAI / Claude SDK；支持自定义执行器及插件、存储、答复验证和产物发布注入 |
| 设计状态 | 两个包已实现 Python 核心；各自 README 是当前接口依据，取代此前 10/16 方法草案 |
| 与业务关系 | 均为可复用基础包，核心源码在 src，入口 main；不依赖 applications、containers 或 modules 内部实现 |
| 轻量原则 | 不在包内管理 SDK 注册表、数据库、联网服务、技能发现、身份系统或业务审批策略 |
| 事务边界 | 包通过外部 store 保存单会话快照；work 快照包含有界事件日志和私有恢复状态；没有跨包事务、Outbox、跨服务事件总线或自动任务重放 |

## 应用如何组合

| 场景 | 责任 |
|---|---|
| 聊天创建工作 | 外部工作控制技能调用 work.create_session / submit；聊天只把 plugins 传给生成器，不硬编码任务工具 |
| 会话关联 | 应用保存 conversation_id 与 session_id 关联；工作可独立使用，一个聊天可关联多个工作；ID 本身不是授权凭据 |
| 工作进度与结果 | 通过 work.get_session 读取，或 stream_events 按游标跟随指定轮次；应用决定展示或汇报时机。当前聊天没有 append_notification，不自动把工作结果写入聊天历史 |
| 人工答复 | 语音、聊天或工作台都调用 work.respond_interaction，并传已认证的 response_ref；宿主 verify_response 核验真实用户、待办及输入绑定 |
| 语音打断 | 应用收到 voice.generation_cancelled 后取消对应聊天生成；工作后台执行独立，只有明确停止工作时调用 work.cancel_run |
| 角色与长期记忆 | 外部通过配置/技能提供；长期记忆提炼可由外部后台处理，不写入聊天核心 |
| 删除聊天 | 不删除或停止关联工作；关联清理由外部应用管理 |
| 身份切换 | 每个身份独立包实例及存储范围；宿主取消订阅、清理界面并决定活动执行的收尾，防止旧响应进入新身份 |

## 外部适配器约束

| 事项 | 约定 |
|---|---|
| 存储 | 宿主选择数据库或文件，提供身份隔离和原子快照保存；一个存储范围只允许一个活跃包实例写入 |
| SDK | 每种 SDK 的适配器实现同一契约；缺失能力明确拒绝。不能把方法名相同视为行为等价 |
| 权限与插件 | 业务权限、工具执行前鉴权、文件授权和技能资源由宿主/受控插件实现；提示词不构成权限或批准 |
| 不确定结果 | 存储异常、停止未确认或进程退出后，先核对状态与外部效果，不盲目重跑副作用 |
| 隔离与取消 | 外部适配器必须响应取消并清理资源；有副作用的工具需受控执行宿主，包不是隔离沙箱 |
| 旧项目依据 | 参考 apps/ai-service 的 ChatService、apps/agent-service 的 work.js / work-executor.js 及语音 work_control 插件；旧工程保持不变 |
| 当前验证 | 包内测试及外部文件存储适配验证；不代表真实 SDK、联网、模型或业务工具已验收 |
