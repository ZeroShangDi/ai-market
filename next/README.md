# 新架构临时根目录

`next/` 是未来项目根目录的暂存位置。新架构实现先在此独立建设，现有工程继续保留在仓库原位，便于原分支更新与合并。当前已建立目录骨架及独立 [Python 语音基础包](packages/voice/README.md)，尚未初始化应用运行工程。

```text
next/
├── applications/       # 业务应用：组合领域能力、页面与业务流程
├── containers/         # 应用宿主工程，支持框架并存或替换
├── devops/             # 构建、部署、发布、升级、备份恢复
├── docs/               # 项目文档与迁移记录
│   └── rules/          # AI 开发规范文档
├── modules/            # 领域模块，边界需经业务分析确认
└── packages/           # 按实际需要提取的共享资源包
```

业务应用统一使用 `applications` 命名。应用组合通过代码与配置表达，不规划可视化组装器。基础能力可以位于工程内部，确需共享时提取到 `packages`。

`containers` 可以包含 PC 网页、移动 APP、桌面或后端工程，但不固定四个目录或四个工程。按实际选型命名并创建；同一用途允许不同框架实现并存。当前暂不预建具体工程。

本分支所有文件改动严格限定在 `next/` 内，外部工程只读参考；安装、构建和测试的输出也必须遵守此边界。

迁移约定见 [迁移说明](docs/migration.md)，开发约定见 [规范索引](docs/rules/README.md)。空目录使用 `.gitkeep` 占位，以便随 Git 保存；有实际文件后可删除占位文件。

`containers` 表示应用宿主工程，不特指 Docker 容器。详见 [运行工程说明](docs/containers.md)。
