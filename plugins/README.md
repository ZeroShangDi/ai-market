# 统一插件目录与协议 v1

状态：源码已统一迁移至本目录，旧路径保留兼容链接；Work 提供独立标准 MCP stdio 入口。代码尚未部署，本次不宣称外部真实客户端和手机已验收。

目标：能力实现可在其他支持 MCP / Agent Skills 的宿主中复用；允许为不同宿主生成不同接入配置。项目不自建工具调用协议，不要求外部宿主识别本项目元数据。

## 1. 标准边界

- 工具、资源与提示词：使用 MCP 官方 SDK，按客户端实际支持版本协商。远程服务使用 Streamable HTTP，本地可执行插件支持 stdio；不把项目 HTTP 路由直接宣称为 MCP。
- 技能：使用 Agent Skills 的 `SKILL.md` 目录格式与必需 frontmatter，正文和引用资源不依赖手机路径。
- 打包：不同宿主的插件外壳、MCP 配置、技能安装路径不同，由 `adapters/` 处理。不存在所有宿主通吃的插件包格式；可移植验收以标准 MCP 客户端和至少一个外部实际宿主为准。
- 本项目 `plugin.json` 仅管理目录、版本、依赖、能力中心展示与配置引用，是项目自己的元数据，不是新的行业标准。外部宿主无需理解它。
- MCP Tasks 扩展仅在双方协商支持时使用。基础兼容路径仍提供普通 MCP 工具：创建任务立即返回任务 ID，随后查询状态、读取记录、答复待办、取消与续聊；不依赖客户端保持一次长连接。

## 2. 统一源码布局

源码布局（旧路径仅作兼容链接，不维护副本）：

```
plugins/
  callphone/                 # 现有业务能力
  work-control/             # 创建、查询、续聊、读取会话及待办操作
  characters/               # 人物包、交流技能和资源清单
  workspace-files/          # 现有工作文件技能
  memory/                   # 优先配置已有开源实现，选型后加入
```

每包可包含：`plugin.json`、`skills/<name>/SKILL.md`、`mcp/`、`adapters/<host>/`、`assets/`、`tests/`、依赖锁文件和许可证。仅技能包无需空的 MCP 服务。角色音频/动画仍按不可变版本发布，运行数据不进入源码目录。

运行配置、密钥、记忆库、会话数据库和用户文件放在独立数据目录。插件声明配置需求，不携带实际凭据；部署者绑定服务地址、账号和数据目录。

## 3. 元数据约定

必需：`id`（小写连字符稳定标识）、`version`（语义版本）、`name`、`description`、`license`、`skills`、`mcpServers`、`dependencies`。

- `skills`：包内相对路径列表，真实存在且可校验，不复制技能正文到客户端。
- `mcpServers`：命名端点定义及支持的传输方式；实现入口或部署地址由宿主适配器解析。不得把任意字符串拼成 shell 命令执行。
- `dependencies`：运行时/服务及版本约束，开源依赖固定版本并保留许可证。
- 可选 `configSchema`：非敏感配置的 JSON Schema；敏感项只声明名称与用途，由宿主秘密存储注入。
- 可选 `hostAdapters`：宿主专用配置生成器及兼容版本。SDK 自带 in-process MCP 作为适配方式，不能成为唯一实现。
- 可选 `x-ai-market`：能力中心展示与本平台专属声明。未知宿主可以忽略；不得承载核心业务算法或唯一权限校验。
- MCP 工具参数、结果及读写提示以服务器公布的 schema 为唯一事实来源；本项目不再手工维护一份会漂移的工具签名。
- 不按语音/文字/事件复制工具。入口来源仅作任务元数据；若某能力确有交互前提，应声明所需宿主能力，不硬编码入口名称。

## 4. 统一调用与触发

文字、语音、计划和事件 → 后端任务入口 → 持久化 Work → 已装载的标准 MCP/技能 → 结果与通知。

触发服务负责时间与时区、事件订阅、去重、并发、预算、启停和通知。MCP 暴露管理这些规则的工具；MCP 自身不是定时器或能自动唤醒任意 AI 的总线。业务判断和工作指引放在插件，底座只实现通用执行生命周期。

每个触发请求绑定服务端核验的用户身份、来源、幂等键与插件版本；模型不可自行传入任意租户/用户 ID。dsh、CC 或其他客户端通过各自鉴权适配连接同一服务，不依赖 Android JavaScript 桥。Work MCP 已复用现有网关账号与设备凭据；独立登录/OAuth 发证尚未实现，不能将共享内部服务密钥分发给普通客户端。

## 5. 待答、挂起与恢复

待答不是长期记忆。必须保存在任务状态中：任务 ID、步骤/检查点、原始问题或审批展示、参数绑定、状态、答复、执行尝试与恢复位置。

目标流程：执行 → 需要输入 → 持久化并挂起、释放并发名额 → 其他独立任务继续 → 用户答复 → 校验待办仍有效 → 排队恢复。

- 同任务只有明确独立、无依赖的步骤才能继续；不能跳过必需参数或审批执行其依赖步骤。
- 答复幂等，已处理/失效的待办拒绝重放；用户拒绝必须保留。
- SDK 恢复游标与工作状态共同保存；进程重启后不能仅靠模型“记得”恢复。
- 外部操作结果未知时先核对，不自动重试副作用。可确定未执行的暂时故障才按策略重试。
- 预留 `maxAttempts`、退避、已用次数与最后失败分类；实际策略后续实现，不以 schema 存在宣称已支持。
- 本阶段不新增“哪些操作自动审批/必须提问”的判断体系；继续沿用现有服务端权限、工具审批与提问机制。

当前实现释放等待名额并暂停执行超时，等待 60 秒后保留待办并结束原执行器。重启后答复可排队恢复 SDK 会话，重新触发的工具仍需重新核验审批。尚未提供同一任务内部独立步骤的依赖调度；其他 Work 可以继续。真实 SDK 长等待联调仍待完成。

## 6. 开源优先

已有标准 MCP 服务：优先由插件声明服务依赖、固定版本、配置和配套技能，不再实现其算法。只有缺少身份隔离、来源追踪、导入导出或接入协议时才增加薄适配，并明确哪些是上游功能、哪些是本项目补充。

记忆候选：官方示例 Knowledge Graph Memory Server（基础实体/关系/观察存储）及 Mem0（更完整的记忆系统）。已优先登记官方 Memory Server 2.0.0 接入定义，未安装或上线。不能只写一句“使用开源记忆”就认为拥有跨账号隔离、中文检索、删除与来源证明；需逐项验证，服务运行与数据管理仍需部署配置。

## 7. 能力中心

页面归属与操作规则见 [能力分类约定](../docs/modules/capability-classification.md)：一个包一个主分类，插件附带条目仅在详情内展示。`catalogType` 为展示元数据，不改变 MCP 或 Agent Skills 标准。

一个注册表汇总同一目录的插件、技能、连接器、MCP 服务及角色能力。来源明确，真实区分“已安装”“已启用”“连接正常”“需要配置”“内置/随角色启用”。不具备独立卸载能力的条目不显示伪卸载按钮。

当前能力中心合并 `catalog.json` 的内置条目与已配置业务插件，Agent 和语音仍使用各自兼容装载器。统一跨进程启停协议尚未实现；内置项只展示，不提供无效开关。安装/停用不能只改 UI。停用阻止新调用，已有任务按明确策略处理，不悄悄取消已获授权的操作。

## 8. 底座改动范围

1. 通用插件注册表和装载器：统一版本、配置及生命周期，替换目前分散目录。
2. 通用 MCP 客户端接入：语音与 Work 复用；移除语音插件直接依赖手机桥的核心能力耦合，保留宿主身份适配。
3. 外部客户端鉴权适配：将不同宿主登录映射到现有用户和权限；不开放内部令牌或绕过审批。
4. 能力中心数据源：从注册表展示全部能力及真实运行状态。
5. Docker 构建、资源发布与路径迁移：更新包路径，旧运行环境不热加载半套新代码；不原地修改已发布角色包。
6. 挂起恢复已进入实现与自动化测试；定时/事件触发、重试与预算仍为后续事项，均不表示已经上线。

前五项属于接入统一协议必需的有限底座适配；第六项明显不是单改插件能完成，不承诺其改动很小。后续具体业务能力尽量只新增插件。

## 9. 迁移验收

逐包迁移并保留兼容适配：业务插件 → Work 控制 MCP → 人物/文件技能 → 能力中心合并 → 开源记忆接入。

每包验证标准客户端 tools/list、tools/call（纯技能包验证格式）、重试幂等、身份隔离、待办一致性、外部宿主使用、版本回退。协议版本与依赖固定后再导出配置；不宣称对所有 MCP 客户端零配置兼容。
