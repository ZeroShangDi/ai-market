# Work 能力插件接入

Work 负责会话、附件、插件装载、工具执行前授权、事件持久化与回放；业务能力放在独立插件目录。手机只连接 Work，按通用协议显示工具进度、授权字段和结果卡片，不识别业务工具名称。

当前首个实现：[客户业务插件](callphone/README.md)。插件由部署配置启用，不从用户附件安装，不提供插件市场或连接器管理页面。

## 包结构与装载

每个包包含 `work-plugin.json`（宿主协议）、`.claude-plugin/plugin.json`（SDK 原生技能命名空间）、`index.js`（activate 入口）以及 `skills/<技能>/SKILL.md`。业务连接器和工具实现放在该包内。

`WORK_CAPABILITY_PLUGINS` 为受管理绝对路径的 JSON 数组，默认 `[]`。Docker 编排已配置 `/app/plugins/callphone`；本地需使用实际绝对路径。包必须位于用户工作区之外，入口不能越出包目录，部署者负责审核插件代码。插件运行在服务进程中，不构成第三方不可信代码隔离沙箱；不向用户命令环境继承业务密钥。

清单示例：

```json
{"schemaVersion":1,"id":"example","entry":"index.js","tools":{"inspect":{"label":"检查内容","risk":1}}}
```

原生清单 `name` 须与 `id` 相同。`activate({sdk,z,config,ctx})` 返回 `{tools,approval?}`：

- `tools` 是 `sdk.tool(...)` 定义数组，名称必须与清单一致；宿主注册为 `mcp__<id>__<tool>`。
- `ctx` 提供当前工作目录、已选资源、服务端可信租户/用户、取消信号及 `emitResult`。插件自行维护连接器配置、后端调用和业务校验。
- `approval(tool,input)` 返回 `[{label,value}]`，用于通用授权卡片。风险 1 自动执行，2/3 按现有机制逐次确认并绑定实际参数；插件负责声明实际副作用，后端仍须执行身份与业务权限校验。
- SDK 从插件技能目录发现流程说明，模型按任务选用技能和工具；技能不替代接口权限及参数校验。

## 通用展示协议

调用 `await ctx.emitResult({title,summary,rows:[{label,status,detail}]})`，宿主校验纯文本字段及数量上限，增加 `plugin_id`，保存为 `plugin_result` 事件。手机按当前运行 ID 渲染摘要与可展开明细；重新进入仍通过事件回放读取，不执行工具。

工具标签来自清单；授权字段来自插件；结果内容来自已执行的插件工具。前端不判断“线索”“拨号”等业务类型，不执行插件 HTML 或脚本。新增业务先复用这套展示；确需新展示形式时，应扩展通用协议，而非加入业务专属分支。

## 调用链

用户上传附件并交办 → Work 创建运行、加载受管理插件 → 模型发现技能与 MCP 工具 → Work 按清单完成授权 → 插件连接器以可信用户身份调用后台 → 后台执行业务并返回核验结果 → 插件发出通用结果事件 → 前端展示并保存历史。

连接器解决“接到哪个系统、怎样认证和调用”；MCP 工具提供“模型可调用的动作”；技能说明“如何组合动作完成任务”；插件把这些内容打包。底座只依赖插件协议。

## 移动端能力中心（2026-10-16）

部署预置包后，用户从应用广场的「能力中心」进入，在「发现」安装到个人能力列表；安装仅启用服务器审核过的包，不下载任意第三方代码。插件详情管理启用、技能开关和卸载；连接器分类连接当前账号；MCP 服务从右上角更多菜单进入，展示插件提供的工具。当前不提供手机端任意 MCP 地址编辑或第三方 OAuth 登录。

全局能力配置按租户/用户持久化在 Work 数据目录的 capabilities 子目录，独立于会话。会话只保存选用插件 ID；加号选用已安装、启用且连接的能力。技能条目选用所属插件并在草稿中指明技能。停止技能只禁止该技能调用，不撤销插件工具；停止插件或断开账号会阻止旧会话后续工具调用，已发出的外部操作不能回滚。

通用接口：GET/POST `/api/v1/mobile/work/sessions/capabilities` 管理当前账号能力，GET/POST `/:sessionId/plugins` 仅查询及选用/移除会话能力。账号检查由插件导出的 `connect` 执行；技能清单需提供与原生技能目录一致的 `id`。前端不包含领域工具名、地址和认证配置。
