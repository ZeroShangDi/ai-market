# 聊天能力插件

新增 AI 能力通过插件交付。语音主流程只装载插件、注册工具并处理音频；能力的提示词、工具参数、连接器和编排均放在插件目录。当前 `work_control` 使用现有 Work HTTP API，不需要额外 MCP 服务；相同连接器与技能可供其他聊天宿主复用。

## 包与装载

每个受管理 Python 包包含 `plugin.json`、`SKILL.md`、`__init__.py`。部署变量 `VOICE_PLUGINS` 是包名 JSON 数组，默认 `["work_control"]`，`[]` 停用全部能力；不能从用户输入、附件或模型输出安装包。插件运行在可信服务进程中，不是第三方代码沙箱。

`activate(identity, context, host)` 返回插件实例：`enabled` 决定是否装载；`execute(name, arguments)` 执行清单中工具；`prepare_notice(notice)` 可将通知整理为口头摘要；可选 `notice_delivered(id)` 只在音频实际播放完成后调用。`identity` 来自签名票据，模型不能提供身份、服务地址或凭据。`context` 提供当前文字会话；`host.request` 是有界、带请求关联的通用宿主通信；`host.emit` 仅发送白名单内已有宿主事件（当前为 `task_proposal`），送达不等于用户确认。

工具清单可声明 `timeoutSeconds`（1–180 秒，默认 60 秒）；底座只负责通用有界执行，插件应为授权和实际操作预留足够时间。公开搜索插件内部等待 120 秒，外层 150 秒包含最多 20 秒手机授权。

插件提示词约束行为，服务端权限和参数绑定负责执行边界。新增宿主能力必须进入受管理白名单，不能把通信接口做成任意 URL 代理。

## 工作控制插件

- `search_web`：聊天中的公开联网搜索，模型自行组织必要关键词，不创建工作。失败、繁忙或耗时不能自动转后台工作。
- `start_work`：只发送现有手机工作申请弹窗，不调用创建会话、创建工作或提交消息接口。用户点击确认后，手机沿用现有鉴权、请求去重和提交路径创建；取消或未确认不执行。工具回执仅表示等待确认，不能报告任务已接收。
- `list_work`、`read_work`：查看状态、历史、产物及待办，支持历史与长消息分页。
- `read_work_activity`：读取运行中的进展、工具调用结果和来源，长事件可以按游标续读。
- `continue_work`：在原任务追加请求，运行中可排队；不能用普通消息替代待办答复。
- `respond_work`：在已说明具体事项且用户随后明确答复后，提交原待办的 binding 和答复，复用工作台 `interactions` 接口。工作台已答复、参数变化、过期或重启后的事项不可重复审批。

新建工作的手机确认路径负责创建 AI 会话和 Work 提交，插件不能直接创建。查看、续聊、审批与事件读取仍经现有手机鉴权和关联会话权限检查；继续已有工作复用请求编号与待办绑定，不能替代审批。确认后的任务独立于语音连接运行。

宿主照旧拉取未读任务事件。插件核对序号、读取事实并通过无工具的模型调用生成简短汇报，播报前重新等待空档；汇报实际播放完成后才加入聊天上下文并开放该摘要对应的口述答复。模型摘要失败回退已有通知文本，仍可口述要求读取详情。通知不标记工作台已读。服务重启与 App 完全退出时的持久化、人工恢复及未读行为沿用 Work。

## 兼容与验证边界

工作控制插件要求 Android 桥声明 `plugin-host-v1`，因此需要配套 App。旧 App 与普通 H5 暂不装载工作控制插件，需使用工作台；不能绕过手机鉴权直接控制任务。新建工作还要求宿主提供 task_proposal 确认弹窗；不支持时只引导用户去工作台，禁止绕过确认直接提交。当前插件协议覆盖旧人物卡中查询自动转工作或无需弹窗的描述。

本次只完成开发与自动检查，尚未部署或生成 APK。真机需确认：查询时继续聊天、结束语音后查询继续、结果空档汇报、口述同意/拒绝/多问题回答、工作台抢先答复、读取旧任务和原会话追问，以及断网重试不重复提交。手机打包前遵循仓库的下次版本提醒。

## 发布一致性

服务启动时将插件 Python 实现、`plugin.json` 和 `SKILL.md` 作为同一进程快照加载。修改插件后必须重启语音服务；不再只热读取参数定义而保留旧函数，避免移除必填参数后出现“工具参数格式不正确”。
